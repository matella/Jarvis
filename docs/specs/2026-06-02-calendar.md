# Calendar (Google read-mirror + local editable)

> Date: 2026-06-02 · Personal-OS module (step 7). **Two halves:** a **read-mirror cache** of Google
> Calendar (OAuth, read-only — not the source of truth) **+** a **local editable** calendar table
> (user docs; the table owns the truth). Keeps the existing ICS read connector for other externals.
> **No write-back to Google in v1** (locked). Inherits the foundation + shell template.

## Access model (locked)

- **Google OAuth read-mirror:** pull the operator's real Google events read-only. OAuth is the one
  place v1 takes on token machinery (refresh-token in `.env`/SecretsProvider, never DB/git/logs).
- **Local editable calendar:** Jarvis/you create/edit events in a local table (auto-run CRUD).
- **ICS** (existing `connectors/calendar.py`): keep for non-Google external calendars (read-only).
- **No write-back to Google** (defer the hard 2-way per foundation). Editing pulls toward the local
  calendar; the Google mirror is display+context only.

## Shape

- **Secrets:** `GOOGLE_OAUTH_CLIENT_ID/SECRET`, `GOOGLE_OAUTH_REFRESH_TOKEN` in `.env` via
  SecretsProvider. A `make google-oauth` (or one-time local consent flow) mints the refresh token,
  pasted into the box `.env` — mirrors the router's `make claude-token` pattern.
- **Migration `0025_calendar`:** `calendar_accounts(id, kind, label, secret_name, schema_version,
  created_at)` (`kind ∈ {google, ics, local}`) + `calendar_events(id, account_id, source,
  external_uid, title, location, description, starts_at, ends_at, all_day, rrule, status,
  source_entity_ref, schema_version, entity_ref, synced_at, created_at, updated_at)`. Google/ICS
  rows are **mirror** (re-syncable, `external_uid` for dedupe); `source=local` rows are **truth**.
  `entity_ref = "calendar:<id>"`. `ids.CALACCT`/`ids.CALEVENT` prefixes.
- **Google connector** (`connectors/google_calendar.py`): OAuth refresh → list events in a horizon →
  upsert mirror rows (deduped by `external_uid`) → emit `calendar.synced`. Egress-guarded.
- **Local tools** (`calendar.*`, on **local** events only, **auto-run** — reversible/low-risk/on-box):
  `calendar.create_event`, `calendar.update_event`, `calendar.delete_event`. `side_effects=false`
  (stays on box; no write-back to Google), `rollback=manual`. Editing a *mirrored* Google event is
  **not allowed** in v1 (read-only) — the UI offers "copy to local" instead.
- **Awareness events:** `calendar.event_created/updated` (local), `calendar.synced` (mirror refresh).
- **Search:** index title+description+location via the shared hook (`source=calendar`).
- **Context:** `events_today()` / `next_event()` / `agenda(range)` for the conversation agent + brief.

## Cross-module + AI

- **"email → calendar event"** (`calendar.create_event`, linked `source_entity_ref=mail:<id>`).
  **"add <recipe> cook night to Friday"**, **"block 2h for the <document> draft"** (task/doc →
  calendar). All local events, ride `entity_ref`.
- **Daily brief:** `events_today()` leads the morning push.
- **Voice:** "what's on today?", "add dentist Tuesday 3pm".

## Events / data

`calendar.synced` (`info`; counts), `calendar.event_created/updated` (local; `entity_ref` +
`correlation_id`), `calendar.sync_failed` (`failure_class`). Mirror rows carry `synced_at`; only
`source=local` rows are truth.

## Frontend

Route `/calendar` + nav + panel: month/week/agenda views merging mirror(Google+ICS) + local events
(visually distinct; mirror = read-only), quick-add (local), event detail (mirror → "copy to local"),
OAuth-connect button. Cmd-K: "what's on <day>", "add event". Theme tokens.

## Testing → acceptance

- **Unit:** event model validation (times, all-day, rrule passthrough); Google sync upsert+dedupe by
  `external_uid` (mocked API); local CRUD tools + grading (auto-run); mirror events **reject** edit
  tools (read-only); search indexing; OAuth refresh uses the `.env` secret (mocked, never logged).
- **Integration (auto-skip, real Google via env):** OAuth refresh + sync pulls real events;
  local create/update/delete; "email → calendar" link resolves.
- **Frontend (vitest):** views render merged sources; mirror read-only + copy-to-local; quick-add;
  OAuth-connect; Cmd-K.
- **Gate:** OAuth read-mirror shows real Google events; local CRUD (auto-run); no write-back to
  Google; daily brief shows today; email→calendar works; secrets never logged; suite + lint green.

## Non-goals

No write-back / 2-way sync to Google (v1). No editing mirrored events (copy-to-local instead). No
invite/RSVP handling. No recurring-event editing UI (rrule stored/displayed, edited as text). No
CalDAV server. Multiple Google accounts allowed by schema, one wired in v1.
